## Adoption and value for the target candidate

In the first thirty seconds, the useful free action is the English Interview path. It can return a saved price, delta and a defendable written explanation, rather than an empty account or an immediate payment requirement. The deeper paid value is actual English course content, private written practice and independently runnable references. This is a stronger proposition than counting tools or agents; willingness to pay remains a hypothesis.

Three meaningful pilot tasks should follow this review:

1. **First 30–60 minutes:** price the free call ticket, write assumptions and hedge direction before its correction, compare numerical checks, self-review the argument, try a conceptual variant, then return to the saved feedback. Measure completion, unexplained stops and whether the learner can explain the units without help. A number copied from the calculator is not evidence of independent understanding.
2. **One focused study session:** select a genuine English rates/curve lesson, derive its convention, retain a written answer and execute the original curve reference outside the application. The course, example and exported script must each state their ticket; different original examples must not be presented as the same calculation.
3. **A two-week return:** reopen an earlier answer and self-review, attempt the unseen variant, use Survival as unranked timed practice, and export only the revision material already exposed. Compare observed errors and explanations over time. Opening pages, downloading a deck, ticking a self-review and obtaining a higher practice score do not independently demonstrate improved interview skill.

These are proposed real-candidate tasks, not completed user research. No real adoption time, retention, satisfaction, hiring outcome or purchase was measured here. The strategy's price tests remain unvalidated; this reviewer does not manufacture a willingness-to-pay answer from a working download.

## Concrete defects found during this integration

### C2-B01 · P1 — retained work is absent from the dashboard continuation model

After an actual submitted private exercise and self-review, `/dashboard` has no link to the generated exercise. After a saved Survival run containing answers and a timeout, it still states **“No submitted learning activity yet.”** The read model has legacy events and Interview, but no projection of the new written-attempt or Survival stores. Existing answers are not lost; reopening their direct URL restores them. The defect is discoverability and a false global empty state.

Initial evidence: core `dashboardAfterWritten` has no exercise href; Survival evidence has `events=0`, no Survival mention and the explicit empty claim. The first Survival run was **answered but not finished**, so the evidence is not a twenty-question completion. This distinction does not make “no submitted learning activity” true.

**Closed by independent retest.** After restarting only the owned fixture process with its existing store, independent HTTP retest confirms the new projection: Pro initially has one written attempt and one self-review with its exact attempt link; Student initially has two runs and three answers with a saved-run link. Both historical averages remain null; the previous event counts remain unchanged. Another Pro reading the first owner's progress receives 403. See `business/integrated/progress-readonly.json`.

The final browser test deliberately added a newer QA attempt, then a review of the original older attempt. The dashboard linked back to that older attempt and restored its exact self-review, rather than always opening the newest submission. Saved Survival activity no longer receives the false empty claim and its chosen run link restores that run. A complete twenty-answer UI run and reload then preserved the server's 7152-point result (equal to the sum of its recorded answers), with no historical average invented. A separate three-wrong-answer run finished with three answered questions, zero lives and zero points. All are test actions using authored keys, not evidence of learner skill. See `business/integrated/final-targeted-retest.json`.

### C2-B02 · P1 — an unsupported RFQ can crash its local illustrations

Submit `Price a worst-of barrier autocall on Euro Stoxx 50 and Nikkei 225, 3 years`. The backend refusal is expected. The UI subsequently loses its input form and reports two uncaught `maturityYears is outside the supported domain.` errors. The unbounded duration regex can match `50 an` at the start of `50 and`, interpreting fifty years; the local vanilla illustration calls the canonical engine outside its thirty-year domain.

**Closed by independent retest.** The worst-of request receives an explained 422 while its editable text remains. An explicit fifty-year ticket receives a local out-of-range refusal, without a useless HTTP request or a silent clamp. No old calculated contract is kept and no uncaught error occurs. A subsequent valid BTC put succeeds in the same form without reload. See `business/integrated/rfq-refusal-final-v2.json`. This closes both the crash and the misleading generic service-diagnosis wording; it does not create the refused model.

### C2-B03 · P2 — wide equations need actual keyboard horizontal scrolling

The six real English long-course views at 390/320 have their full authored lesson counts (curve 9, structured products 10, stochastic 10) and no document overflow.
